# 硬件说明文档

项目：2026 TI 电赛 H 题 车载平衡滚球运动控制系统
平台：WHEELTEC **C07A 核心板 V1.1**（MSPM0G3507SPTR）+ **S28A 底板 REV 15.0**

核心板版本很要紧：V1.1 与 V1.0 在 I2C 上拉、IO 串阻、引出排针三处不同，
见 §2.1。本文按 **V1.1** 编写。

本文是硬件全貌与外设资源说明。具体怎么插线看 [接线指导.md](接线指导.md)。

文中所有数值均取自 `generated/ti_msp_dl_config.c/h` 与各模块厂家手册，
不是估算值。凡是我无法在本机核实的，都集中列在 §11。

## 1. 系统总览

```
                    ┌──────────────────────────┐
   12V 电池 ────┬──▶│ S28A 底板 12V→5V→3V3     │
                │   │  C07A 核心板 MSPM0G3507  │
                │   └──┬────┬────┬────┬────┬───┘
                │      │    │    │    │    │
                │   I2C0  UART1 TIMA1 GPIO TIMG7
                │      │    │    │    │    │
                │      ▼    ▼    ▼    ▼    ▼
                │   幻尔  K230D TB6612 编码器 │
                │   巡线   视觉  ├─驱动轮A×2   │
                │   8路          └─驱动轮B     │
                │                             ▼
                └────────────────────────▶ D36A ──▶ 42步进
                       12V                          （横梁倾角）
```

两条控制回路：

- **底盘巡线**：巡线传感器 → 转向 PD → 左右轮速度环 PI → TB6612 → 编码器反馈
- **横梁平衡**：K230D 视觉给球位 → 平衡 PD → 步进转角 → 横梁倾斜

## 2. 主控芯片 MSPM0G3507

| 项 | 参数 |
|---|---|
| 内核 | Arm Cortex-M0+ |
| 封装 | **LQFP-48（PT）** |
| 主频 | 80 MHz（SYSPLL CLK2X 输出） |
| Flash | 128 KB，等待周期 2 |
| SRAM | 32 KB |
| 供电 | 3.3 V（底板提供） |
| IO 电平 | 3.3 V，绝对最大 VDD+0.3 V ≈ 3.6 V |
| 5V 容忍引脚 | **仅 PA0、PA1**（绝对最大 5.5 V） |

封装这一条很关键：核心板是 48 脚版本。
之前 syscfg 里写的是 LQFP-64(PM)，导致 SysConfig 接受了 PB4/PB12/PB13 这些
48 脚封装上根本不存在的引脚。现在已改为 LQFP-48(PT)，配置阶段就能挡住这类错误。

### 2.1 核心板 V1.1 vs V1.0（影响本项目的部分）

按厂家 `C07A硬件更新内容记录.txt`，V1.1 相对 V1.0 改了五项：
去掉 USER 按键改用 BLS、引出 IO 增加串阻限流、更换 LDO、走线调整、
B8/B18/B19 引到板子右上角。其中三项落在本项目的引脚上：

| 项 | V1.0 | V1.1（当前） | 对本项目的影响 |
|---|---|---|---|
| PA0/PA1 上拉 | 无 | **R11/R12 各 10 kΩ 到 5 V** | 巡线 I2C 已有板载上拉，不要再加 |
| 引出 IO 串阻 | 只有 ESD 管 | ESD 管 + **约 22 Ω 串阻** | 限流保护，对 I2C/PWM/编码器均无实质影响 |
| PB8/PB18/PB19 | 未引出 | 右上角 `J1` 排针（`PB8B/PB18B/PB19B`） | PB18 变为物理可达，但仍不选它做 K230 RX，见 §7 |
| PB8 上的按键 | 核心板 SW1 + 10 kΩ 上拉 | **核心板按键已删除** | PB8 的上拉现在只靠 MCU 内部，见 §8 |

串阻的量级说明：更新记录写"20 电阻"，原理图上标的是 22 Ω（标准值）。
22 Ω 串在 I2C 上不改变上拉强度，只与总线电容构成极小的 RC，
400 kHz 下可忽略；串在 ST1 脉冲和编码器输入上同样无影响；
串在电池 ADC 分压（10k/1k，源阻抗约 909 Ω）上引入约 2% 的附加阻抗，
对这种慢速直流测量也无影响。

`R11/R12` 这一条是我从 V1.1 原理图上 `PA0A/PA1A` 附近的两个 10K 到 5V 读出的
（V1.0 同一位置的 D4 只有 ESD 阵列）。我读的是 PDF 渲染图，
上电前用万用表在 PA0/PA1 对 5V 量一下电阻可以确认。

### 2.2 时钟树（来自 `SYSCFG_DL_SYSCTL_init()`）

```
SYSOSC (32 MHz) ──▶ pDiv=2 ──▶ 16 MHz ──▶ qDiv=4 ──▶ 80 MHz
                                          （×(4+1)）      │
                                                          ▼
                              CLK2X (rDiv=1) ──▶ HSCLK ──▶ MCLK = 80 MHz
                                                             │
                                                             ├─▶ CPUCLK = 80 MHz
                                                             └─▶ ULPCLK = 40 MHz
                                                                （ULPCLK_DIV_2）
MFCLK 已使能
HFXT 外部晶振：未使用（disableHFXT），时钟全部来自内部 SYSOSC
```

即 `(32 / pDiv) × (qDiv + 1) = (32 / 2) × 5 = 80 MHz`，
CLK2X 作为 MCLK 源（`sysPLLMCLK = CLK2X`），CLK0/CLK1 均关闭。

**这里有个容易踩的坑：定时器的时钟域取决于它在哪个电源域。**

| 电源域 | 定时器 | 时钟 |
|---|---|---|
| PD0 | TIMG0、TIMG8 | **ULPCLK = 40 MHz** |
| PD1 | TIMG6、TIMG7、TIMG12、TIMA0、TIMA1 | **80 MHz** |

已实测验证：
- `TIMER_0`（TIMG0，PD0）：prescale 31 + load 12499 → 10 ms，反推 40 MHz ✓
- `PWM_0`（TIMA1，PD1）：prescale 0 + period 8000 → 10 kHz，反推 80 MHz ✓

算定时器分频时用错时钟域，周期会差一倍。

### 3.1 空闲资源

改口后释放出的引脚原本是 `PA7`、`PA9`、`PA22`、`PA24`、`PA27`
（原 MPU6050 与蓝牙、CCD、手柄接口上的信号），
其中后四个已分配给 `J6` 上的步进闭环反馈：
PA22 = A 相、PA24 = B 相、PA27 = PWM 绝对位置（TIMG8 CC1）、PA9 = Z 相。

**现在只剩 `PA7` 一个空闲引脚。**

未使用的定时器：TIMA0、TIMG6、TIMG12。
未使用的通信外设：I2C1、UART2、SPI0、SPI1、CAN。

### 3.2 中断与优先级

Cortex-M0+ 只有 4 个优先级（0 最高，3 最低）。
本项目**只显式设置了一处优先级**，其余全部是默认的 0：

| 中断 | 处理函数 | 位置 | 优先级 |
|---|---|---|---|
| GPIO Group1 | `GROUP1_IRQHandler` | `drivers/encoder_driver.c:39` | 0（默认） |
| TIMG0 | `TIMER_0_INST_IRQHandler` | `control/vehicle_controller.c:287` | 0（默认） |
| UART1 RX | `K230_INST_IRQHandler` | `app/app_main.c:120` | 0（默认） |
| TIMG7 零事件 | `PWM_STEPPER_INST_IRQHandler` | `drivers/stepper_driver.c:156` | **3**（显式设置） |

含义：编码器、控制节拍、K230 接收三者同级，互相**不会抢占**，
只会按到达顺序排队执行。步进计数中断优先级最低，不会打断上面三个。

这个安排是有意的：步进 ISR 在 5 kHz 上限时每秒进 5000 次，
虽然每次只有几条指令（80 MHz 下占用远低于 1%），但它只负责累加步数，
延迟一点无所谓，不该挤占控制回路和编码器边沿。

编码器 ISR 必须够快 —— 它是四路边沿共用一个 Group1 中断，
漏一个边沿就丢一个计数。

## 4. 底盘驱动：TB6612 + 直流减速电机

### 4.1 驱动模块 D103A（TB6612FNG 精简版）

底板 `H9`/`H12` 已经把 12V、5V、四路方向和两路 PWM 全部布好，不需要额外接线。

| 信号 | MCU 引脚 | 说明 |
|---|---|---|
| PWMA | PB2 | TIMA1 CC0，10 kHz |
| PWMB | PB3 | TIMA1 CC1，10 kHz |
| AIN1 / AIN2 | PA14 / PA13 | 电机 A 方向 |
| BIN1 / BIN2 | PA16 / PA17 | 电机 B 方向 |

方向逻辑（`board_hardware.h` 中的宏）：

| IN1 | IN2 | 状态 | 宏 |
|---|---|---|---|
| 1 | 0 | 正转 | — |
| 0 | 1 | 反转 | — |
| 0 | 0 | 滑行（高阻） | `HW_MOTOR_x_COAST()` |
| 1 | 1 | 刹车（短路制动） | `HW_MOTOR_x_BRAKE()` |

PWM 周期 8000 ticks @ 80 MHz = 10 kHz，占空比直接写 0~8000
（`HW_MOTOR_PWM_PERIOD_TICKS`）。10 kHz 在人耳听觉上限之上，电机不啸叫。

### 4.2 编码器

两路 AB 相增量式编码器，接底板 `J1`/`J2`（与电机输出同一插座）。

| 信号 | MCU 引脚 | 中断 |
|---|---|---|
| E1A / E1B | PA25 / PA26 | GPIO Group1，双相都开中断 |
| E2A / E2B | PB20 / PB24 | 同上 |

**解码方式：双边沿计数（2 倍频），不是 4 倍频。**
`GROUP1_IRQHandler` 里对 A 相和 B 相各自的边沿都计数，
通过读另一相的电平判断方向：

```c
if (A 相边沿) count += (B 相为高) ? +1 : -1;
if (B 相边沿) count += (A 相为高) ? -1 : +1;
```

分辨率换算（`drivers/encoder_driver.c`）：

| 项 | 值 | 宏 |
|---|---|---|
| 编码器线数 | 13 线/电机轴转 | `ENCODER_LINES_PER_MOTOR_REV` |
| 边沿倍数 | 2 | `ENCODER_EDGE_FACTOR` |
| 减速比 | 30 : 1 | `ENCODER_GEAR_RATIO` |
| **合计** | **780 counts / 轮子转一圈** | 13 × 2 × 30 |

转速公式：`rpm = count × 60000 / (780 × sample_ms)`，采样窗口 20 ms
（`SPEED_SAMPLE_MS` = `CONTROL_PERIOD_MS` × 2）。

`Encoder_TakeCounts()` 用 `__disable_irq()` 包住"读取 + 清零"，
避免读的瞬间 ISR 又加了一个计数导致丢步。

换电机或换编码器要同步改这三个宏，否则速度环的反馈标定全错。

## 5. 横梁驱动：D36A + 42 步进电机

### 5.1 模块构成

D36A 是双路步进驱动，核心是两颗 **ATD5984**（杭州中科微），
板上还有散热风扇、12V→5V 稳压、3V3 线性稳压、电源开关和 6 位拨码。
本项目只用第 1 路。

| 信号 | MCU 引脚 | 外设 | 说明 |
|---|---|---|---|
| ST1 | PB16 | TIMG7 CC1 | 脉冲，**上升沿有效** |
| DIR1 | PB17 | GPIO | 方向 |
| EN1 | PA12 | GPIO | **高使能，低休眠** |

EN1 接 ATD5984 的 SLEEP 脚，所以是高有效：高 = 上电锁力，低 = 松开线圈。
这与 A4988/DRV8825 相反，旧代码按低有效写的，方向是错的。
生成代码里 EN1 初始化为 `clearPins`，因此**上电时驱动处于休眠状态**，安全。

三根线取自底板 `J10`。注意 `J10` 与手柄座 `U3` 在原理图上是**并联**的
（`U3` = `GND / 3V3 / PB17 / PB16 / PA12 / PA27`，共用后三个信号中的三根），
两个座子只能二选一：步进接 `J10` 时不能插手柄，否则两端同时驱动同一网络。

`U3` 的第 6 脚 PA27 现在还兼作步进反馈的 PWM 位置输入（§5.7），
所以 `U3` 与 `J10`、`J6` 一共冲突 4 根线，手柄接口在本项目里彻底不可用。
本项目不用手柄，所以不构成实际限制，但改板或加手柄时必须记住。

### 5.2 步进参数

| 项 | 值 | 宏 |
|---|---|---|
| 步距角 | 1.8°（两相混合式） | — |
| 整步数 | 200 步/圈 | `STEPPER_FULL_STEPS_PER_REV` |
| 细分 | 16（拨码 1/2/3 全 OFF） | `STEPPER_MICROSTEPS` |
| **脉冲数/圈** | **3200** | `STEPPER_PULSES_PER_REV` |
| 频率上限 | 5 kHz（待核实，见 §11） | `STEPPER_MAX_FREQ_HZ` |
| 频率下限 | 16 Hz | `STEPPER_MIN_FREQ_HZ` |

5 kHz 上限对应 5000/3200 ≈ 1.56 转/秒 ≈ 94 rpm。
下限 16 Hz 是定时器能表达的最慢频率（1 MHz / 65536 ≈ 15.3 Hz），
比这更慢的指令直接停机保持，不去"爬行"。

### 5.3 为什么用硬件 PWM 而不是定时器翻转引脚

参考工程用定时器中断翻转 IO 产生脉冲。本项目改成硬件 PWM，理由：

- 脉冲间隔完全由硬件决定，不受中断负载影响。控制回路、编码器、
  串口接收都在抢 CPU 时，软件翻转的脉冲会抖动，步进会丢步或啸叫。
- 改速度只需改定时器周期，CPU 全程不参与脉冲输出。

TIMG7 的计数时钟：80 MHz（PD1 域）/ prescale 80 = **1 MHz**，
所以周期值 = 1000000 / 目标频率 − 1，占空比固定 50%。

### 5.4 为什么选 TIMG7 而不是 TIMG8

PB16 这个引脚 TIMG7 和 TIMG8 都能接出来（分别是 mux 6 和另一个功能号），
但 SDK 的外设特性表（`PWM.syscfg.js`）显示：

| 定时器 | 影子 LOAD | 影子 CC |
|---|---|---|
| TIMG7 | 有 | 有 |
| TIMG8 | **无** | **无** |

没有影子寄存器时，`DL_Timer_setLoadValue` 立即生效。
如果此刻计数器已经越过了新的周期值，它就会一路跑到 0xFFFF 才回绕 ——
**每次变速都可能多出一个最长 65 ms 的畸形脉冲**。
横梁平衡回路是频繁小幅变速的，这个缺陷会持续注入扰动。

所以选 TIMG7，并开启 `enableShadowLoad`，
CC 更新方式设为 `ZERO_EVT`（零事件时生效），周期与占空比都在周期边界原子更新。

> 补充：**TIMG8 现在已被步进反馈的 PWM 位置捕获占用**（§5.7）。
> 它缺影子寄存器这件事对捕获没有影响 —— 捕获只读 CC 值，
> 不在运行中改周期，唯一的写操作是 ZERO 中断里重装计数器，本来就要求立即生效。
> 缺影子寄存器只对"输出 PWM 且频繁变速"这个场景致命，对输入捕获无所谓。

### 5.5 停机与启动的时序处理

影子寄存器带来一个副作用：**计数器停着的时候没有零事件，
所有影子写入都不会生效**。所以 `drivers/stepper_driver.c` 里分了三条路径：

- `pulses_start()`：先关影子、切 IMMEDIATE，写 LOAD/CC/计数清零，
  再恢复 ZERO_EVT + 影子，最后启动计数器
- `pulses_retune()`：仅改速度，直接写 LOAD 和 CC，两者都缓冲到下一个零事件
- `pulses_stop()`：切 IMMEDIATE、CC 写 0，再停计数器（保证停在低电平）

`Stepper_SetSpeed()` 的分支：超上限则钳位，低于下限则停机，
**方向变化时先停再启动**（ATD5984 在脉冲边沿锁存 DIR，
中途改方向可能走错一个微步），同向变速走 retune。

### 5.6 步数统计

`PWM_STEPPER_INST_IRQHandler` 在每个 `DL_TIMER_IIDX_ZERO` 上累加一步。
TIMG7 没有重复计数器可以分频，所以只能一个脉冲一次中断。
已确认 `ZERO_EVENT` 在 `EDGE_ALIGN_UP` 模式下是合法的 PWM 中断源
（SDK `PWMTimerMSPM0.syscfg.js` 的事件选项列表只按通道数和 TimerA 能力过滤，
不按 pwmMode 过滤）。

`s_position` 和 `s_dir` 都是 `volatile`，Cortex-M0+ 上 32 位读是单指令原子操作，
所以主循环调 `Stepper_GetPosition()` 不需要临界区。

### 5.7 闭环反馈：`J6` 上的四路编码器信号

驱动器的编码器反馈接底板 `J6`，四根都是 MCU 输入。接线细节看
`docs/接线指导.md` §4.4，这里只讲为什么是这个分配。

| `J6` 脚 | MCU 引脚 | PINCM | 信号 | 配置 |
|---|---|---|---|---|
| 1 | PA22 | 47 | A 相 | GPIO 输入，上拉，无中断 |
| 2 | PA24 | 54 | B 相 | GPIO 输入，上拉，无中断 |
| 3 | PA27 | 60 | PWM 绝对位置 | TIMG8 CC1，联合捕获 |
| 4 | PA9 | 20 | Z 相 | GPIO 输入，上拉，无中断 |

#### 硬件 QEI 在这个座子上不成立

MSPM0 的 QEI 要求同一个定时器的 CCP0 **和** CCP1 同时引到外部引脚。
把 LQFP-48 全部定时器的 CCP0/CCP1 可用性排了一遍，
`J6` 这四个脚**没有一个能当任何定时器的 CCP0**，
所以 A/B 只能软件解码，换排线顺序也救不回来。

#### PA24 只能是纯 GPIO，这条约束定死了整张表

PA24 的定时器选项只有三个，全部已占用：

| PA24 可选定时器 | 现状 |
|---|---|
| TIMG0 | 100 Hz 控制节拍 |
| TIMG7 | 步进 ST1 脉冲（§5.4） |
| TIMA1 | 两路直流电机 PWM |

所以 PA24 不可能承载 PWM 位置信号，PWM 只能落在 PA27（TIMG8 空闲），
B 相被挤到 PA24。这不是随手排的，是唯一可行解。

#### PWM 绝对位置：单脚联合捕获

用 `DL_TIMER_CAPTURE_COMBINED_MODE_PULSE_WIDTH_AND_PERIOD`，
一个引脚同时测出高电平宽度和整周期，占空比取比值，
**载波频率漂移自动抵消**，不需要标定载波。

SysConfig 的官方例子把信号绑在 `ccp0Pin` 上，而 PA27 只能是 CCP1。
查 SDK 源码 `dl_timer.c` 的 `DL_Timer_getInChanPairConfig()` 确认：
`inputChan = 1` 时 CC0 的 ISEL 被设成 `DL_TIMER_CC_IN_SEL_CCPX_PAIR`，
即 **CC0 去观察 CCP1 引脚**，所以只绑 CCP1 也能做联合捕获。
代价是两个通道的边沿角色互换 —— CC0 抓周期沿、CC1 抓宽度沿，
因此重装中断用的是 `CC0_DN` 而不是例子里的 `CC1_DN`。

计数器向下计数，读法：

```c
period_ticks = LOAD - CC0;    /* 整周期 */
high_ticks   = LOAD - CC1;    /* 高电平宽度 */
duty         = high_ticks / period_ticks;   /* period 为 0 时不能除 */
```

时钟预算：**TIMG8 在 PD0**，BUSCLK = ULPCLK = 40 MHz（不是 80 MHz，
PD1 的定时器才是 80 MHz，这一步算错就整体差一倍），
预分频 4 得 10 MHz 计数、0.1 µs 分辨率；
16 位计数器 LOAD = 65534 → 满量程窗口 6.5534 ms → **载波下限约 152 Hz**。

联合捕获模式不会自动重装，必须在每个上升沿（`CC0_DN`）调
`HW_STEPPER_POS_CAP_RELOAD()`，漏了就只能捕到第一个周期。

> **当前状态：引脚和外设已配好，但还没接进固件。**
> `SYSCFG_DL_STEPPER_POS_CAP_init()` 在外设层使能了 `CC0_DN` 和 `ZERO`，
> 但项目里没有任何地方调 `NVIC_EnableIRQ()`，也没有 `TIMG8_IRQHandler` 的实现。
> 这不会出问题（NVIC 没使能就进不了 ISR，标志位挂着也不会空转），
> 但重装也不会发生，所以现在只能捕到第一个周期。
> 写驱动时要补三件事：
> 1. 实现 `STEPPER_POS_CAP_INST_IRQHandler`，`CC0_DN` 里调 `HW_STEPPER_POS_CAP_RELOAD()`，
>    `ZERO` 里把读数标记为无效（`ZERO` 意味着 6.5534 ms 没来上升沿，即掉线）；
> 2. `NVIC_EnableIRQ(HW_STEPPER_POS_CAP_IRQN)`；
> 3. `HW_STEPPER_POS_CAP_START()`（定时器配的是 `DL_TIMER_STOP`，不自启动）。
>
> A/B/Z 三个脚同理，现在只有宏，没有解码驱动。

#### A/B/Z 故意不开中断

GPIOA 与 GPIOB 共用一条 NVIC 线（Group1，见 §3.2）。
`GROUP1_IRQHandler`（`drivers/encoder_driver.c`）目前只读清四个轮子编码器的标志位。
给 A/B/Z 开中断而不同步扩展这个 handler 的后果是：
它们的标志位永远挂着 → ISR 反复重入 → **轮子编码器一起失效**，
不是"新功能不工作"而是"旧功能被拖死"。

所以这三个脚现在是纯电平读取，靠控制中断轮询。
100 Hz 轮询下每个正交状态至少要采到两次才不丢步，
跟不上高速编码器 —— 这一路用来判方向和配合 Z 相做圈计数，
绝对位置以 PWM 那一路为准。
要改成中断驱动的话，`config/board.syscfg` 里 STEPPER_ENC 那段注释写了
`GROUP1_IRQHandler` 需要补什么。

## 6. 巡线传感器：幻尔 LineFollower（I2C）

### 6.1 硬件

| 项 | 值 |
|---|---|
| 型号 | Hiwonder LineFollower（手上资料是 8CH v1.0） |
| 当前通道数 | 6（可切 8） |
| 供电 | **5 V** |
| 接口 | I2C（另有 UART 可选，本项目不用） |
| MCU 引脚 | PA0 = SDA，PA1 = SCL |
| 总线速率 | 400 kHz |

选 PA0/PA1 是被迫的，不是随意选的：传感器是 5 V 器件，
而**这两个脚是本芯片上唯一的 5 V 容忍引脚**（绝对最大 5.5 V，
其余引脚只有 VDD+0.3 V ≈ 3.6 V）。挪到别的口会超出 IO 绝对最大额定值。

上拉电阻有两个来源：**C07A V1.1 核心板上的 R11/R12（10 kΩ 到 5 V，
直接挂在 PA0A/PA1A 上）**，以及传感器板自带的上拉（该板为 5 V Arduino 设计）。
两者并联约 3 kΩ，400 kHz 够用。V1.0 核心板没有 R11/R12。
生成代码里 SDA/SCL 配的是 `DL_GPIO_RESISTOR_NONE` + `enableHiZ`，
即完全依赖外部上拉，这与硬件一致。**不要再额外加上拉，更不要加到 3V3。**

### 6.2 通信协议

| 项 | 值 | 宏 |
|---|---|---|
| 7 位地址 | `0x5D` | `HW_LINE_SENSOR_I2C_ADDR` |
| 状态寄存器 | 5，1 字节，每位一路，1 = 黑线 | `HW_LINE_SENSOR_REG_STATE` |
| 模拟值寄存器 | 6，N×2 字节小端 | `HW_LINE_SENSOR_REG_ANALOG` |
| 阈值寄存器 | 22，可写 | `HW_LINE_SENSOR_REG_THRESHOLD` |

读时序（照厂家 Arduino 例程的 `write()` + `requestFrom()` 复现）：
先发 1 字节寄存器地址 + STOP，再发读请求收 N 字节。

控制回路只用状态寄存器；模拟值和阈值留着做标定用。

位序：厂家例程用 `(temp[0] >> len) & 0x01` 依次打印 `State1..StateN`，
即 **bit0 = 板上 S1**；八路板丝印 S1…S8 从左到右（Hiwonder 字样和 KEY 键
在 S8 那一端）。按连接器朝车尾的装法，S1 在车体左边，所以
`HW_LINE_SENSOR_BIT0_IS_LEFT = 1`，驱动内部反转成本项目约定。
板子装反（连接器朝前）会有同样的镜像症状，那时应该转正板子而不是改这个宏。

### 6.3 通道数可切换的设计

改一个宏就够，派生项全部自动推导：

```c
#define HW_LINE_SENSOR_COUNT (8U)   /* 当前八路板 */
```

派生项：滤波状态数组、权重表、全黑掩码 `LINE_SENSOR_ALL_MASK`、
OLED 通道循环次数与误差列位置。权重按 `2i − (N−1)` 计算：

| 通道数 | 权重序列 | 转向误差范围 |
|---|---|---|
| 6 | −5, −3, −1, +1, +3, +5 | ±5.0 |
| 8（当前） | −7, −5, −3, −1, +1, +3, +5, +7 | ±7.0 |

状态位用 `uint8_t` 承载，所以 8 路是上限（代码里有 `#error` 守卫）。

误差单位是**半个探头间距**，所以同一物理偏移下的数值不随通道数变化，
`LINE_KP` 不需要按通道数缩放。变的是饱和上限（±5 → ±7），
线压到最外侧一路时修正量约为原来 1.4 倍。真正决定 `LINE_KP` 的是
**探头间距**：间距越小，同样偏移算出的数值越大，增益要按反比调小。

> 停车横线检测的两个阈值 `APP_STOP_LINE_MIN_INSTANT_CHANNELS (3)` 和
> `APP_STOP_LINE_WINDOW_CHANNELS (4)` 是**绝对通道数**，目前仍是六路时定的值。
> 八路下 3/8 比 3/6 更容易命中，可能误触发停车。见 §11。

### 6.4 I2C 读取放在主循环，不在中断里

这是本次改造最重要的一个结构决定。

阻塞式 I2C 传输要几十微秒，如果放进 100 Hz 控制中断，
一旦传感器拉长时钟（clock stretching）或掉线，
控制中断就会被卡住，而**此时电机还锁在上一次的占空比上** —— 车会失控冲出去。

所以拆成两半：

| 函数 | 调用位置 | 频率 | 做什么 |
|---|---|---|---|
| `LineSensor_Poll()` | 主循环 | 5 ms | 阻塞读 I2C，写入缓存 |
| `LineSensor_Update()` | 控制中断 | 10 ms | 只对缓存做滤波，不碰总线 |

5 ms 是控制周期的一半，保证每个控制周期都能看到不超过一个周期的新鲜采样。
主循环末尾的 `__WFI()` 会被控制定时器（10 ms）和每个编码器边沿唤醒，
所以循环转得足够快，撑得住这个节奏。

容错：单次 I2C 超时（`LINE_I2C_TIMEOUT_LOOPS` = 20000 次空转）
保持上一次采样；**连续 5 次失败**（`LINE_SENSOR_FAIL_LIMIT`）
才清成"丢线"并把 `LineSensor_IsOnline()` 置假。
`s_fail_count` 初值就是上限值，所以必须真正成功读到一次才会报在线。

滤波：`LINE_SENSOR_FILTER_N` = 3，需要连续 3 次采样一致才改变输出，
抑制路面反光和地砖缝造成的单次跳变。

## 7. 视觉模块：K230D（UART）

| 项 | 值 |
|---|---|
| 型号 | 正点原子 ATK-DNK230D（Kendryte K230） |
| 接口 | UART1，115200 8N1 |
| MCU 引脚 | PB6 = TX（MCU 发），PB7 = RX（MCU 收） |
| 电平 | 3.3 V，与 MSPM0 直连，不需电平转换 |
| 接收方式 | RX 中断 + FIFO |

选 PB6/PB7 有两个原因：一是这一对物理相邻（原蓝牙模块座 `H8`，
座子上还自带 5 V/GND），符合"引脚位置靠近"的要求；
二是改造前的 RX 用的是 **PB18，而 PB18 没有引到 S28A 底板的任何排针上** ——
摄像头接收接不了线。

这里要按核心板版本区分：**C07A V1.1 把 PB8/PB18/PB19 引到了板子右上角的
`J1` 排针**（3 脚，`PB8B/PB18B/PB19B`，V1.0 没有这个排针）。
所以在 V1.1 上 PB18 物理上是可达的，"接不了线"只对 V1.0 和"经底板排针"成立。
即便如此 PB6/PB7 仍然更优：`J1` 只有 3 个信号脚、不带电源，
而 UART1 的 RX 功能在 PB18 上未必可用，还要额外飞线；
`H8` 是现成的 4 脚座，插上就能用。结论不变，但理由要说准。

供电：`H8` 座子上带 5 V 和 GND，接线上可以直接取电。约束在电流预算 ——
底板这一路 5 V 出自 P03B（12 V→5 V），还要同时供 TB6612 逻辑和巡线传感器，
而 K230D 跑视觉时瞬时电流不小。先从 `H8` 取电试，盯主控复位和 OLED 花屏
两个现象；出现任一就单独引一路 5 V，只与底板共地。
P03B 的电流规格本地资料里没有（只有一个资料包索引 txt），
K230D 的实测功耗也没有，所以这里给不出定量结论。

### 7.1 曾经的一个隐藏故障

改造前 `app_main.c` 里的接收中断函数名写的是 `K230_UART_IRQHandler`，
**这个符号在生成的头文件和 `startup_mspm0g350x_uvision.s` 的中断向量表里都不存在**。
也就是说它只是个普通函数，永远不会被调用，一个字节都到不了 `Camera_FeedByte()`。
正确的宏是 `K230_INST_IRQHandler`（展开为 `UART1_IRQHandler`），已修正。

这类错误编译器不会报警 —— 名字写错只是多定义了一个没人调的函数。

## 8. 显示与人机交互

### 8.1 OLED（软件 SPI）

| 信号 | MCU 引脚 |
|---|---|
| RST | PB14 |
| DC | PB15 |
| SCL | PA28 |
| SDA | PA31 |

软件模拟 SPI，速度慢，所以主循环里 **300 ms 刷一帧**。

有一处时序要求：开机第一帧在**中断还没打开时**绘制。
软件 SPI 的位翻转过程若被中断打断，面板会锁存到错位的数据，
表现是屏幕一直黑着。`app_main.c` 里 `oled_show_mode_select()`
的首次调用刻意放在所有 `NVIC_EnableIRQ()` 之前。

OLED 第 7 行显示巡线各路状态；
`LineSensor_IsOnline()` 为假时整行显示 `-`，这是判断 I2C 通不通最快的手段。

### 8.2 按键

| 按键 | MCU 引脚 | 有效电平 |
|---|---|---|
| BLS（核心板） | PA18 | **高**（按下为高），内部下拉 |
| S28A_KEY（底板） | PB8 | 低（按下接地），内部上拉 |
| RESET | 硬件复位脚 | 不能当 GPIO 用 |

两个按键的内部电阻方向相反，生成代码里分别是
`KEY_BLS` → `DL_GPIO_RESISTOR_PULL_DOWN`、
`S28A_BUTTON_S28A_KEY` → `DL_GPIO_RESISTOR_PULL_UP`，与上表一致。

BLS 的高有效不是笔误。厂家资料里专门有一句
（`3.原理图\按键电路设计说明.txt`）：**"C07A 的 BLS 按键电路设计与 USER
按键电路设计不同，不可直接套用 BLS 按键检测逻辑"**。
V1.1 已经删掉了 USER 按键，所以板上只剩 BLS 这一种电路，
照着网上按 USER 键写的低有效例程会一直读到"按下"。

PB8 还有一处版本差异：**V1.0 核心板上有 SW1 + 10 kΩ 上拉挂在 PB8 上，
V1.1 把这个按键删了**。所以在 V1.1 上，PB8 的上拉完全依赖 MCU 内部上拉
（已在生成代码里配好），底板按键按下时拉低。这个方向是对的，不用改；
但如果以后换回 V1.0 核心板，PB8 上会同时存在核心板按键和底板按键，
两个并联，任意一个按下都会触发。

### 8.2.1 PA18 的另一重身份：BSL 引导

"BLS" 这个丝印指的是 **BSL**（Bootstrap Loader，ROM 里的串口引导程序）。
在 MSPM0 上，**PA18 是默认的 BSL invoke 引脚** —— 复位释放的瞬间
ROM 引导程序会采样它，采到高电平就进入串口下载模式而不启动用户程序。

这一条对本项目的实际影响：

- **上电或按 RESET 的时候，不要按着这个键。** 按着上电会停在 BSL 里，
  表现是程序完全不跑、OLED 不亮，很容易误判成"死机"或"程序烧坏了"。
  松手重新上电即可恢复。
- 正常运行期间按它没问题，BSL 只在复位那一刻采样。
- 内部下拉（`DL_GPIO_RESISTOR_PULL_DOWN`）保证了不按键时是低电平，
  所以默认行为是正常启动。这也是为什么这个脚必须配下拉而不是上拉 ——
  配成上拉会导致每次上电都进 BSL。

V1.1 删掉了独立的 USER 按键，把 BSL 键兼作用户按键，所以这个"双重身份"
是 V1.1 独有的；V1.0 上用户按键在 PB8，与 BSL 无关。

这一条我没能从本地数据手册核实（PDF 文本提取失败），
依据是 MSPM0 系列的默认 BSL 配置加上丝印命名，已列入 §11。
不过"上电时别按着它"这个建议本身无论如何都是对的。

主循环里固定 10 ms 扫描一次（`Button_Update()`）。
这个节奏是必须的：如果每次循环都调，同一个 `now_ms` 会被重复采样很多次，
双击/长按的时间窗口判断就乱了。

### 8.3 状态 LED

PB9。**核心板上就有一个蓝色 LED 挂在 PB9 上**，接法是
`3V3 → R5 1 kΩ → L1 → PB9`，也就是**低电平点亮**（灌电流约 3 mA）。
底板资源表里也把 PB9 列为 LED，两个 LED 并在同一个脚上，
都是被 MCU 拉低点亮，不冲突，只是负载翻倍。

有两点要注意：

1. **极性是低有效**，不是高有效。想点亮就 `HW_GPIO_LOW`，想灭就 `HW_GPIO_HIGH`。
2. 生成代码里 PB9 初始化为 `DL_GPIO_clearPins`，而应用代码**从来没有再动过它**
   （`HW_STATUS_LED_PORT` / `HW_STATUS_LED_PIN` 两个宏定义了但无人使用）。
   所以现在的实际表现是：**上电后蓝灯一直亮着**，不闪也不灭。
   这不会损坏任何东西，但它作为"状态指示"是没意义的 ——
   想让它真的指示状态，得在应用里写驱动逻辑，并记住低有效。

## 10. 时序与节拍汇总

| 任务 | 周期 | 触发源 | 位置 |
|---|---|---|---|
| 控制回路（速度环 + 转向） | 10 ms（100 Hz） | TIMG0 中断 | `vehicle_controller.c` |
| 速度采样窗口 | 20 ms | 控制回路计数 2 次 | `SPEED_SAMPLE_MS` |
| 平衡回路 | 20 ms（50 Hz） | 主循环 | `BALANCE_PERIOD_MS` |
| 巡线 I2C 读取 | 5 ms | 主循环 | `LineSensor_Poll()` |
| 按键扫描 | 10 ms | 主循环 | `Button_Update()` |
| OLED 刷新 | 300 ms | 主循环 | `oled_show_mode_select()` |
| 步进脉冲 | 16 Hz ~ 5 kHz | TIMG7 硬件 | 无 CPU 参与 |
| 步进实际用到的范围 | ≤ 3000 步/秒 | `BALANCE_OUTPUT_LIMIT` | 平衡回路输出限幅 |
| 电机 PWM | 10 kHz | TIMA1 硬件 | 无 CPU 参与 |

主循环结构：扫按键 → 比赛状态机 → 巡线 I2C → OLED → `__WFI()` 休眠。
`__WFI()` 被控制定时器和编码器边沿唤醒，所以循环实际转速远高于 5 ms。

平衡回路的输出限幅是 3000 步/秒，低于 `STEPPER_MAX_FREQ_HZ` 的 5000，
所以正常工作时步进不会撞到频率上限，`Stepper_SetSpeed()` 里的钳位是保护性的。
3000 步/秒 ÷ 3200 脉冲/圈 ≈ 0.94 转/秒。

| 9 | `R11/R12`（10 kΩ 到 5 V）是否真在 PA0/PA1 上 | 从 V1.1 原理图渲染图读出，V1.0 无此电阻 | 万用表量 PA0/PA1 对 5V 的电阻；若不是 10 k 左右，重看 §6.1 上拉那段 |
| 10 | 核心板确实是 V1.1 | 按你的说法记为 V1.1 | `C07A不同版本识别方法.png` 我这边打不开，外观区分方法没读到；最直接的判据是**板子右上角有没有那个 3 脚 `J1` 排针**（V1.1 有，V1.0 没有） |
| 11 | PA18 是 BSL invoke 引脚 | 依据是 MSPM0 默认 BSL 配置 + 丝印命名，本地数据手册文本提取失败 | 按着该键上电，若程序不跑（OLED 不亮）即证实；无论如何"上电别按着它"都成立 |
| 12 | 八路板探头中心距 | 未量。板宽 107 mm / 8 路，推算约 12~13 mm；六路板本地无任何资料，间距未知 | 卡尺量一下。若与六路板不同，`LINE_KP` 要按间距反比缩放，见 §6.3 |
| 13 | 停车横线阈值仍是六路时的值 | `APP_STOP_LINE_MIN_INSTANT_CHANNELS = 3`、`APP_STOP_LINE_WINDOW_CHANNELS = 4`，按你的要求这次没动 | 八路下 3/8 比 3/6 灵敏，留意弯道或斜压引导线时误停；按比例折算应是 4 和 5 |
| 14 | **驱动器编码器输出是 3.3 V 还是 5 V** | 未知。`J6` 四个脚绝对最大值都是 3.6 V，全芯片只有 PA0/PA1 耐 5 V 且已被巡线 I2C 占用 | **量到 5 V 必须加电平转换再插**，直连会烧口。这项没量之前别插 `J6`（§5.7） |
| 15 | `J6` 四个脚的物理顺序 | 1→4 = PA22/PA24/PA27/PA9，从底板原理图 REV 15.0 网表推出 | 对丝印图核对。同批解析出的 `J10` = PA12/PB16/PB17 与已知一致，可信度较高但仍需实物确认 |
| 16 | PWM 绝对位置输出的载波频率 | 未知。当前预分频只覆盖 **152 Hz 以上** | 低于此值捕获会溢出，需调大 `CAPTURE1.timerClkPrescale` 并重新生成（§5.7） |
| 17 | A 相与 B 相是否需要对调 | 未知，软件解码的正方向未验证 | 解码转向与实际相反时，对调 `J6` 第 1、2 脚接线或在解码代码里取反，二者选一 |

另外一个环境限制：**本机没有 ARM 工具链**
（Keil、armclang、arm-none-eabi-gcc 都不存在），所以固件从未编译过。
SysConfig 生成已验证通过且幂等；`line_sensor.c` 的逻辑在 host-gcc 打桩环境下
按当前配置（8 路、`BIT0_IS_LEFT=1`）跑过一轮：8 路权重逐路核对为
−7,−5,−3,−1,+1,+3,+5,+7，S1 归一化到最高位并画在屏幕最左，
中心两路误差为 0，全黑有效、全白丢线、断裂图形被拒，
第 7 行列位置落在 0..16（一行 21 列）。

`J6` 反馈的宏（§5.7）也在 host-gcc 打桩环境下验过一轮：
A/B/Z 三个位掩码互不重叠且独立解码，一个完整正交循环 00→01→11→10 逐态对上；
捕获算术按 1 kHz / 25 % 载波（周期 10000 拍、高电平 2500 拍）反解正确，
载波放慢 20 % 后占空比读数不变（证实比值法能抵消载波漂移）；
未捕到边沿时周期读数为 0（调用方必须先判零再做除法）；
`RELOAD` 写入值等于 `LOAD`。
这只验证了宏展开和算术，**没有验证真实定时器行为**。
整体编译和实机运行需要你在 Keil 里做。

## 12. 改造前存在的四个硬件级缺陷

记录在此，避免以后回退时重新踩坑。

| # | 问题 | 后果 |
|---|---|---|
| 1 | syscfg 声明 LQFP-64(PM)，实际是 LQFP-48(PT) | SysConfig 放行了 PB4/PB12/PB13 等 48 脚封装上不存在的引脚 |
| 2 | K230 RX 用 PB18 | PB18 未引到 S28A 底板排针，摄像头接收无法接线（V1.1 核心板 `J1` 上有 PB18，但需飞线且不带电源） |
| 3 | `Stepper_Tick()` 无人调用，且 EN 按低有效驱动 | 步进电机从来没转过 |
| 4 | 中断函数名写成 `K230_UART_IRQHandler` | 向量表里无此符号，摄像头接收中断从未触发 |

前三个是配置与接线层面的，第四个是纯命名错误 ——
编译器不会报警，只会多一个没人调用的函数。

## 13. 配置修改流程

**引脚定义的唯一来源是 `config/board.syscfg`。**

```
修改 config/board.syscfg
        ↓
运行 tools/generate_syscfg.bat
        ↓
生成 generated/ti_msp_dl_config.c/h   ← 不要手改
        ↓
按需更新 board/board_hardware.h 的 HW_* 抽象层
```

`board_hardware.h` 是硬件抽象层：上层代码只用 `HW_*` 宏，
不直接引用生成的符号。换引脚时改动收敛在 syscfg + 这一个头文件里。

回滚参考：`config/board.syscfg.bak` 是改造前的版本，确认无误后可删。
