# 引脚接线文档与接线指导

适用项目：2026 TI 电赛 H 题 车载平衡滚球运动控制系统
主控：WHEELTEC **C07A 核心板 V1.1**（MSPM0G3507SPTR，**LQFP-48 PT 封装**）
\+ **S28A 底板 REV 15.0**

> **核心板版本**：本文按 **V1.1** 写。V1.1 的判据是板子右上角有一个 3 脚排针
> （`J1`，引出 PB8/PB18/PB19），V1.0 没有。
> 与接线有关的差异只有一条：**V1.1 在 PA0/PA1 上自带 10 kΩ 上拉到 5V**，
> 所以巡线 I2C 不要再自己加上拉（详见 §3.1）。

本文所有引脚均以 `generated/ti_msp_dl_config.h` 的实际生成结果为准，
连接器归属以 `4.C07A适配S28A底板原理图.pdf` 网表为准。

## 0. 安全须知（先读这一段）

1. **先接地，再接电源，最后接信号。** 步进驱动、传感器、K230D 与底板必须共地，
   否则信号电平没有参考点，轻则通信不上，重则烧口。
2. **PA0 / PA1 是本芯片上唯一两个 5V 容忍引脚**（绝对最大 5.5V）。
   其余引脚绝对最大值只有 VDD+0.3V ≈ 3.6V。
   幻尔巡线传感器是 5V 器件，所以 I2C 必须走 PA0/PA1，不要挪到别的脚。
3. **D36A 的 5V 输出不要接到 S28A 的 5V 排针。** S28A 已有自己的 12V→5V 模块，
   两个 5V 源并联会互相灌电流。D36A 与底板之间**只接 GND**。
4. 上电前检查 D36A 接口丝印（丝印在板子背面），电源接反会直接烧驱动。
5. 通电前确认巡线传感器底部没有金属物接触，该板背面引脚裸露，短路会烧板。
6. **步进闭环反馈的四根信号（`J6`）不是 5V 容忍的。** 这四个脚（PA22/PA24/PA27/PA9）
   绝对最大值都是 3.6V。驱动器的编码器输出若是 5V 推挽，必须先做电平转换，
   直接插会烧口。详见 §4.4。

## 1. 供电架构

| 供电对象 | 取电位置 | 说明 |
|---|---|---|
| 底板 + 核心板 | 电池 12V → `DC1` → 电源开关 `SW1` → 12V 母线 | 底板自带 12V→5V 模块（`H15`/`H16`） |
| TB6612 电机驱动 | 底板 `H9`/`H12` 已布好 12V + 5V | 不需额外接线 |
| D36A 步进驱动 | 电池 12V，接 D36A 的 `Vin+` / `Vin-` | 可用 D36A 的"输入电源并联输出接口"级联 |
| 幻尔巡线传感器 | 5V，建议取底板 `J4`（5V/GND 排针） | 传感器工作电压 5V，勿接 3V3 |
| K230D | 5V，`H8`（原蓝牙座）自带 5V/GND | 峰值电流大，见下方说明 |
| OLED | 3V3，取底板 `J9`（3V3/GND 排针） | |

D36A 与底板共地：从 D36A 的 `GND` 引一根线到底板任意 GND（`J4`/`J9` 都有 GND）。

## 3. 巡线传感器接线（幻尔 LineFollower，I2C）

### 3.1 接线

传感器板上有一个专用 4 针排针，丝印是 `5V GND SDA SCL`，直接用它最省事。
（板上另有 `5V GND TX RX` 4 针给 UART 用，以及一排 16 针全信号引出，本项目不用。）

| 传感器 | 接到 | 说明 |
|---|---|---|
| 5V | `H5` 的电源脚 | 原理图 REV 15.0 确认 `H5` 是 **5V**（带 C4 退耦） |
| GND | `H5` 的 GND | `H5` 第 1 脚 |
| SDA | PA0（`H5`） | 5V 容忍脚 |
| SCL | PA1（`H5`） | 5V 容忍脚 |

四根线都在 `H5` 上，不需要另外从 `J4` 引电源。`H5` 的信号顺序按原理图是
`GND / PA1 / PA0 / …`，第 7 脚是 PA7（原 MPU6050 的 INT，本项目不用）。
上电前用万用表复核一次电源脚电压。

上拉电阻：**C07A V1.1 核心板自带 R11/R12 两个 10 kΩ 上拉到 5V，就在
PA0A/PA1A 上**（V1.0 没有这两个电阻，这是 V1.1 新加的）。
幻尔传感器板自己通常也有上拉到 5V，两者并联后大约 3 kΩ，
400 kHz 下的上升时间是够的。

**所以不要再自己加上拉**，尤其不要加到 3V3 —— 那会和板载的 5V 上拉打架
（3V3 上拉的一端被 5V 上拉顶到 5V 以上，形成反向灌流）。
总线读不通时先查地址、共地和学习校准，不要先动上拉。

如果你手上是 **V1.0** 核心板（无 R11/R12），传感器板的上拉就是唯一来源；
示波器看 SDA/SCL 空闲不是高电平时，才在 PA0/PA1 各加 4.7 kΩ 上拉到 **5V**
（跟随传感器板的电平域，PA0/PA1 耐 5V）。

### 3.2 通信协议（已在 `drivers/line_sensor.c` 实现）

| 项 | 值 | 代码中的宏 |
|---|---|---|
| I2C 地址 | `0x5D` | `HW_LINE_SENSOR_I2C_ADDR` |
| 状态寄存器 | 5，读 1 字节，每位一路 | `HW_LINE_SENSOR_REG_STATE` |
| 模拟值寄存器 | 6，读 N×2 字节，小端 | `HW_LINE_SENSOR_REG_ANALOG` |
| 阈值寄存器 | 22 | `HW_LINE_SENSOR_REG_THRESHOLD` |
| 速率 | 400 kHz | `LINE_I2C_BUS_SPEED_HZ` |

状态字节的位序：厂家例程用 `(temp[0] >> len) & 0x01` 依次打印 `State1..StateN`，
即 **bit0 = 传感器板上的 S1**。S1 在车体的左边还是右边取决于你怎么装板子。

### 3.3 通道数与位序配置

改 `board/board_hardware.h` 两个宏即可，其余代码不用动：

```c
#define HW_LINE_SENSOR_COUNT        (8U)   /* 当前八路板 */
#define HW_LINE_SENSOR_BIT0_IS_LEFT (1U)   /* S1 在左边 */
```

权重由通道数自动推导：6 路是 ±1/±3/±5，8 路是 ±1/±3/±5/±7。

八路板（LineFollower_8CH v1.0）的接线和六路完全一样：IIC 口同为
5264-4PIN（5V/GND/SDA/SCL），仍走 H5 的 PA0/PA1。耗流 85 mA @ 5V。
板子 107 × 31.2 × 10.57 mm，比六路宽，装之前先比一下车头位置，
两个长条孔可前后微调。

**重要：传感器出厂需要先做学习校准才能正常识别**，
按板上 `KEY` 键按厂家教程校准一次，否则读回来的状态位全是 0 或全是 1。

## 4. 步进驱动 D36A 接线

### 4.1 控制信号

D36A 的"电机控制输入接口"是两列，**丝印在板子背面**。
左列 `ADC EN2 DIR2 ST2 GND`（第 2 路），右列 `5V EN1 DIR1 ST1 GND`（第 1 路）。
本项目只用第 1 路，接右列：

| D36A | MCU 引脚 | 底板取点 | 说明 |
|---|---|---|---|
| ST1 | PB16 | `J10` | 脉冲输入，**上升沿有效，必须给 PWM** |
| DIR1 | PB17 | `J10` | 方向 |
| EN1 | PA12 | `J10` | **低电平休眠，高电平使能** |
| GND | 底板任意 GND | `J4`/`J9` | 必接，共地 |
| 5V | **不接** | — | 底板已自带 5V 源，见 §0.3 |
| ADC | 不接 | — | 电池电压已由底板 PA15 分压测量 |

`J10` 正好只有这三个信号（PA12 / PB16 / PB17），这也是选它的原因。

> **冲突警告：`J10` 与手柄座 `U3` 是并联的。**
> 原理图上 `U3`（HC-1.25-6PWT，丝印"手柄"）是
> `GND / 3V3 / PB17 / PB16 / PA12 / PA27`，
> 与 `J10` 共用 PB17 / PB16 / PA12 三根信号线。
> 所以**步进驱动接在 `J10` 上时，绝对不要再插手柄模块** ——
> 两边会同时驱动同一根线，轻则步进乱走，重则两个输出对顶烧管子。
> 这两个座子只能二选一。
>
> `U3` 的第 6 脚 PA27 现在还兼作步进反馈的 PWM 位置输入（§4.4），
> 所以本项目里 `U3` 与 `J10`、`J6` 共 4 根线冲突，手柄接口彻底不能用。

ST1 只有高低电平是不动的，必须有上升沿——这就是本项目用硬件 PWM
（TIMG7 CC1，占空比 50%）而不是软件翻转引脚的原因。

### 4.2 拨码开关设置

6 位拨码：**1/2/3 设细分，4/5/6 设电流**。
注意厂家真值表里 **1 = 拨到 ON（导通），0 = 断开**，
这是开关位置不是引脚电平（123 带上拉，断开时引脚是高）。

细分（对应代码里的 `STEPPER_MICROSTEPS`）：

| MS1 | MS2 | MS3 | 细分 | 代码应设 |
|---|---|---|---|---|
| 1 | 1 | 1 | 不细分 | 1 |
| 0 | 1 | 1 | 2 | 2 |
| 0 | 1 | 0 | 4 | 4 |
| 1 | 0 | 0 | 8 | 8 |
| **0** | **0** | **0** | **16** | **16 ← 当前代码默认** |
| 1 | 0 | 1 | 32 | 32 |

**当前代码假定 16 细分，所以拨码 1、2、3 三个全部拨到 OFF（断开）。**
若要改细分，同步修改 `drivers/stepper_driver.h`：

```c
#define STEPPER_MICROSTEPS      (16U)   /* 与拨码 1/2/3 保持一致 */
```

电流（4/5/6 = CUR1/2/3），先从最小档试起，够力矩就停：

| CUR1 | CUR2 | CUR3 | 等效电流 |
|---|---|---|---|
| 0 | 0 | 0 | 1.44 A |
| 0 | 0 | 1 | 1.22 A |
| 0 | 1 | 0 | 0.93 A |
| 0 | 1 | 1 | 0.83 A |
| 1 | 0 | 0 | 0.77 A |
| 1 | 0 | 1 | 0.70 A |
| 1 | 1 | 0 | 0.59 A |
| 1 | 1 | 1 | 0.55 A（最小，建议起步档）|

电流越大力矩越大，但发热和耗电也越大。建议 4/5/6 先全拨 ON（0.55 A），
横梁带不动再逐档加。

注意：拨码是**同时设置两路**的，改细分/电流对第 1、2 路一起生效。

### 4.3 电机与电源

- 步进电机用板上"电机A接口"白色 4 pin 排线直插，省去杜邦线。
  42 步进是六线电机，实际只用 `A+ A- B+ B-` 四根。
- `Vin+` / `Vin-` 接电池 12V，注意极性。
- 板载散热风扇默认一直转，别让杜邦线卡进风扇。
- ATD5984 工作时发热正常，别用手直接摸。

### 4.4 步进闭环反馈接线（`J6`，4 根）

闭环步进驱动的编码器反馈接底板 `J6`（4 脚排针），四根都是 **MCU 输入**：

| `J6` 脚 | MCU 引脚 | 信号 | MCU 侧配置 |
|---|---|---|---|
| 1 | PA22 | A 相 | GPIO 输入，内部上拉，**无中断** |
| 2 | PA24 | B 相 | GPIO 输入，内部上拉，**无中断** |
| 3 | PA27 | PWM 绝对位置输出 | TIMG8 CC1，联合捕获（占空比 + 周期） |
| 4 | PA9 | Z 相 | GPIO 输入，内部上拉，**无中断** |

> **电平警告（会烧口，先看这条）**
> 这四个脚绝对最大值都是 VDD+0.3V ≈ **3.6V**，
> 本芯片的 5V 容忍脚只有 PA0/PA1，且已被巡线 I2C 占用（§0.2）。
> 接线前先用万用表量一下驱动器编码器输出的高电平：
> - 量到 3.3V → 直连即可。
> - 量到 5V → **必须加电平转换**。四路可以用一片 74LVC245（3V3 供电）
>   或四个 1 kΩ + 2 kΩ 分压。分压只对慢信号够用，PWM 位置那一路
>   载波高的话建议用芯片，不要用分压。

> **接插件冲突：`J6` 与 CCD 接口、手柄座 `U3` 共用信号线。**
> `J6` 的 PA22 / PA27 / PA9 三根线同时出现在 CCD 接口上，
> PA27 还出现在手柄座 `U3` 第 6 脚。
> 所以插了 `J6` 之后，**CCD 和手柄模块都不能再插**，三个座子只能用 `J6`。

#### 为什么 A/B 相是软件解码

MSPM0 的硬件 QEI 要求同一个定时器的 CCP0 与 CCP1 都引到外部脚上。
把 LQFP-48 全部定时器的 CCP0/CCP1 可用性排了一遍，`J6` 这四个脚
**没有任何一个能当 CCP0**，所以硬件 QEI 在这个座子上不成立 ——
这跟四根线怎么排顺序无关，换排法也一样。A/B 只能软件解码。

PA24 的定时器选项只有 TIMG0（100 Hz 控制节拍）、TIMG7（步进 ST1）、
TIMA1（电机 PWM），三个全被占用，所以 PA24 只能当纯 GPIO，
PWM 位置信号只能落在 PA27（TIMG8 空闲）。这也是上面那张表里
B 相被排到 PA24 的原因，不是随便选的。

#### A/B/Z 目前只能轮询，没有开边沿中断

GPIOA 和 GPIOB 共用一条 NVIC 中断线（Group1），
`GROUP1_IRQHandler`（`drivers/encoder_driver.c`）现在只读清四个轮子编码器的标志位。
如果给 A/B/Z 开了中断而不同步扩展这个 handler，
它们的标志位会一直挂着、ISR 反复重入，**连轮子编码器一起卡死**。

所以现在这三个脚是纯电平读取，靠控制中断里轮询采样。
要上边沿中断的话，先改 `GROUP1_IRQHandler` 让它认并清掉这三个脚的标志位，
具体要加什么写在 `config/board.syscfg` 里 STEPPER_ENC 那段注释上。

轮询的采样率决定了能跟上的最大转速：100 Hz 控制中断下每个正交状态
至少要采到 2 次才不丢步，所以别指望它数高速编码器 —— 这一路主要用来判方向
和配合 Z 相做圈计数，绝对位置读 PWM 那一路更稳。

#### PWM 绝对位置怎么读

PA27 走的是**单脚联合捕获**：CC0 锁存整周期，CC1 锁存高电平宽度，
占空比取两者比值，所以载波频率漂移会自动抵消，不需要标定载波。

```c
uint32_t period = HW_STEPPER_POS_CAP_PERIOD_TICKS();
uint32_t high   = HW_STEPPER_POS_CAP_HIGH_TICKS();
/* period 为 0 表示还没捕到完整周期，此时不要做除法 */
```

TIMG8 挂在 PD0，BUSCLK = ULPCLK = 40 MHz，预分频 4 得 **10 MHz** 计数
（0.1 µs 分辨率）；16 位计数器 LOAD = 65534，满量程窗口 6.5534 ms，
即**载波低于约 152 Hz 会溢出**。真实载波低于这个值就把预分频调大
（改 `config/board.syscfg` 里 `CAPTURE1.timerClkPrescale` 再重新生成）。

这个模式不会自动重装计数器，必须在每个上升沿（`CC0_DN`）中断里调
`HW_STEPPER_POS_CAP_RELOAD()`，别漏掉。

> **现在只有引脚和宏，还没有驱动代码。**
> 中断在外设层是开着的，但 NVIC 没使能、也没有 `TIMG8_IRQHandler`，
> 所以接上线之后读数不会自动更新（只能捕到第一个周期）。
> 这一步是接线层面的准备，解码和捕获驱动要另外写，
> 详见 `docs/硬件说明.md` §5.7 末尾列的三件事。
> 所以第 6 节调试顺序里插上 `J6` 之后**暂时看不到反馈数据，这是预期的**，
> 不是接线问题。

## 5. K230D 接线（UART）

### 5.1 接线

| K230D | MCU 引脚 | 说明 |
|---|---|---|
| RX | PB6（MCU TX） | **交叉接**：MCU 发 → K230 收 |
| TX | PB7（MCU RX） | K230 发 → MCU 收 |
| GND | `H8` 的 GND | 必接 |
| 5V / VIN | `H8` 的 5V | 座子自带，但先读 §5.2 |

PB6/PB7 在**底板**上有两个座子：`H8`（默认焊接）与 `U5`，
两个都是 `PB6 PB7 GND 5V`，二选一，取一个即可。建议用 `H8`。

> **别插错座子：`U5` 这个位号在两块板上都有，含义完全不同。**
> **底板**的 `U5` 是蓝牙座（`PB6 PB7 GND 5V`）—— 这个可以插 K230D。
> **核心板**的 `U5` 是 OLED 座（`HX PM2.54-1X6P`，
> 引脚是 `GND / 3V3 / PA28 / PA31 / PB14 / PB15`）—— 插 K230D 进去，
> 摄像头的 TX/RX 会怼到 OLED 的时钟和数据线上。
> 本文凡写 `U5` 一律指**底板**的那个。为省事，直接用 `H8`。

波特率 115200，8N1，与 `K230_BAUD_RATE` 一致。
电平：K230D 与 MSPM0 都是 3.3V IO，直连即可，不需要电平转换。

### 5.2 供电注意

`H8` 座子上就有 5V 和 GND，所以**接线上**可以直接从这里取电。
真正的问题是电流预算：底板这一路 5V 来自 P03B（12V→5V）降压模块，
同时还要供 TB6612 逻辑和巡线传感器，而 K230D 跑视觉时瞬时电流不小。

推荐做法：**先从 `H8` 直接取电试**，同时盯住两个现象 ——
主控是否复位、OLED 是否闪烁或花屏。任一出现就说明 5V 被拉垮了，
这时再给 K230D 单独引一路 5V（独立降压模块或它自己的 Type-C），
只与底板共 GND。

我没有 P03B 的电流规格（本地只有一个 `4.P03B电源模块（12V转5V降压）资料包.txt`
的资料包索引，不含手册），也没有 K230D 的实测功耗数据，
所以这里给不出"够不够"的定量结论，只能按上面的顺序试。

### 5.3 需要你确认的一点

本地 `相关资料\k230D` 只有元器件手册和封装库，**没有开发板原理图**，
所以我无法确定 K230D 排针上 UART TX/RX 具体是第几脚。
请对着板上丝印找 UART 的 TX/RX（或查正点原子 ATK-DNK230D 在线文档），
接线时记住是**交叉接**。

## 6. 上电调试顺序

按这个顺序做，出问题容易定位：

1. **只接主控 + OLED**，上电。OLED 应显示模式选择界面。
   不亮先查 3V3 和 PA28/PA31/PB14/PB15 四根线。
   核心板上的蓝色 LED 会一直亮着，这是正常的（低电平点亮，
   生成代码把 PB9 初始化为低且应用里没再动过），不是故障。

   > **上电时不要按着 BLS 键。** PA18 兼作 BSL 引导脚，
   > 复位瞬间被拉高会进串口下载模式，表现就是程序完全不跑、OLED 不亮。
   > 遇到"怎么烧完就黑屏"先松手重新上电。
2. **接巡线传感器**（先不接步进）。传感器板 `PWR` 灯应亮。
   按厂家教程做一次学习校准。
   看 OLED 第 7 行：正常显示每路状态；显示 `------` 说明 I2C 读不通
   （`LineSensor_IsOnline()` 为假）。按这个顺序查：共地 → 5V 供电 →
   学习校准做过没有 → I2C 地址（扫一遍总线）。
   **不要先动上拉**，V1.1 核心板上 R11/R12 已经把上拉做好了。
3. **验位序**（八路板已按 S1 在左设好，这一步是确认）。用胶带只盖住 S1 那一端
   最外侧那颗探头，同时看两处：传感器板上哪颗 LED 亮（硬件真值），
   OLED `IR:` 那八位里哪一位是 `1`。
   - 板上 S1 亮、屏幕**最左**位是 1 → 正确，继续。
   - 板上 S1 亮、屏幕**最右**位是 1 → 把 `HW_LINE_SENSOR_BIT0_IS_LEFT` 取反。
   - 盖的是 S1 那头却是 **S8** 响应 → **板子装反了**，转 180° 装正，别改宏。

   这里的"左"指**车尾朝你、车头朝前时的左手边**。OLED 在核心板上，
   如果你站在车头那侧看屏幕，你眼里的左正好是车的右，别弄混。

   位序错了不只是显示难看：转向误差符号也是反的，一上电就往错方向修正。
   所以这一步确认完再让车落地跑。
4. **接 D36A**：先只接 GND + EN1 + DIR1 + ST1，**电机先不插**，
   12V 先不上。上电后测 EN1 应为低（代码初始化时 EN 是清零的，驱动开机休眠）。

   > 闭环反馈的 `J6` 这一步**先别插**。等第 5 步电机能转起来之后，
   > 用万用表量驱动器编码器输出的高电平，确认是 3.3V（或已加好电平转换）
   > 再插，见 §4.4 的电平警告。插 `J6` 前先把 CCD 和手柄模块拔掉。
5. 插电机，上 12V，跑一个低速指令（几百 steps/s）。
   电机不转就用示波器看 ST1 有没有方波；有方波不转就查细分拨码和电流档。

   电机能转之后再接 `J6`，用示波器在驱动器侧（还没插到底板时）逐根验一遍：
   - **A/B 相**：慢转时两路方波相位差 90°，幅值确认是 3.3V 还是 5V。
   - **Z 相**：每转一圈出现一次窄脉冲。
   - **PWM 位置**：量载波频率，**必须高于 152 Hz**，低了要改预分频（§4.4）。

   四根都对上再插 `J6`。插上后 A/B 相靠轮询采样，只能跟慢速，
   高速下丢状态是预期行为，不是接线问题。
6. **确认方向**：给正的 `Stepper_SetSpeed()`，看横梁往哪边倾。
   与控制律期望的方向相反时，最简单的办法是在 `balance_controller.c` 里
   给 `speed_cmd` 取反，或者把电机 A+/A- 两根线对调。
7. **最后接 K230D**，串口通了再联调整车。

## 7. 代码侧关键约定（接线相关）

| 宏（`board/board_hardware.h`） | 当前值 | 含义 |
|---|---|---|
| `HW_LINE_SENSOR_COUNT` | 8 | 巡线通道数（当前八路板） |
| `HW_LINE_SENSOR_BIT0_IS_LEFT` | 1 | bit0 是否为最左路（S1 在左） |
| `HW_LINE_SENSOR_I2C_ADDR` | 0x5D | 传感器 I2C 地址 |
| `HW_STEPPER_EN_ACTIVE_LEVEL` | 1 | EN 高有效（对应 D36A 高使能） |
| `STEPPER_MICROSTEPS`（`stepper_driver.h`） | 16 | 必须与拨码 1/2/3 一致 |
| `STEPPER_FULL_STEPS_PER_REV` | 200 | 1.8° 步距角 |
| `STEPPER_MAX_FREQ_HZ` | 5000 | 脉冲频率上限，见 §8 |
| `HW_STEPPER_ENC_READ_A/B/Z()` | — | `J6` 三个反馈脚的电平读取（轮询） |
| `HW_STEPPER_POS_CAP_TICK_HZ` | 10000000 | PWM 位置捕获的计数频率（0.1 µs） |
| `HW_STEPPER_POS_CAP_LOAD` | 65534 | 捕获满量程，对应 6.5534 ms / 152 Hz 下限 |
| `HW_STEPPER_POS_CAP_PERIOD_TICKS()` | — | 整周期计数值，为 0 表示尚未捕到边沿 |
| `HW_STEPPER_POS_CAP_HIGH_TICKS()` | — | 高电平计数值，除以周期得占空比 |
| `HW_STEPPER_POS_CAP_RELOAD()` | — | ZERO 中断里必须调用，手动重装计数器 |

巡线 I2C 的读取只发生在主循环（`LineSensor_Poll()`，5 ms 一次），
100 Hz 控制中断里的 `LineSensor_Update()` 只对缓存做滤波、不碰总线。
这样传感器掉线或拉长时钟时不会把控制中断卡住。
连续 5 次读失败会退化成"丢线"状态。

## 8. 仍需你在实物上确认的项

这些我在本机无法验证，接线时请一并核对：

1. **K230D 排针 TX/RX 的具体位置** —— 本地资料没有开发板原理图（§5.3）。
2. ~~传感器的地址与寄存器号~~ —— **已确认**，现用的就是 8 路版
   （`LineFollower_8CH v1.0`），手册明确 `0x5D` 为固定地址，
   STATE=5、ANALOG=6/8…20、THRESHOLD=22/24…36，与代码一致。
   读不通时先查学习校准做过没有，再扫总线。
3. **`H5` 座子的供电电压** —— 已按原理图（REV 15.0, 2025-07-16）确认：
   `H5` 电源脚接 **5V**，带 C4 0.1 µF 退耦，所以传感器电源可以直接从 `H5` 取，
   不必额外从 `J4` 引线。上电前用万用表复核一次即可（我读的是 PDF 渲染图，
   量一下是几秒钟的事）。
4. **`J10` 三个脚的物理顺序** —— 网表确认 `J10` 就是 PA12/PB16/PB17 三个信号，
   但哪个脚对应哪个信号请照底板丝印确认（丝印图在
   `相关资料\7.S28A底板相关资料\1.S28A底板资料\1.C07A搭配S28A底板丝印图.jpg`）。
5. **`STEPPER_MAX_FREQ_HZ` 的 5 kHz 上限** —— 手册 3.2 节提到 STEP 有具体频率范围，
   我没读到那一页。若手册给的上限不同，改 `stepper_driver.h` 里这个宏。
6. **步进正方向与横梁倾斜方向的对应关系**（§6.6）。
7. **`J6` 四个脚的物理顺序** —— 表里的 1→4 = PA22/PA24/PA27/PA9 是从底板原理图
   REV 15.0 网表推出来的，请照丝印图再核对一次（§4.4、§9）。
8. **驱动器编码器输出的高电平是 3.3V 还是 5V** —— 这四个脚都不耐 5V，
   量到 5V 必须加电平转换才能插（§4.4 电平警告）。**这一项没量之前别插 `J6`。**
9. **PWM 绝对位置输出的载波频率** —— 当前预分频只覆盖 **152 Hz 以上**，
   实测低于这个值要调大 `config/board.syscfg` 里的 `CAPTURE1.timerClkPrescale`
   并重新生成（§4.4）。
10. **A 相与 B 相是否需要对调** —— 软件解码出的转向与实际转向相反时，
    把 `J6` 第 1、2 脚两根线对调，或在解码代码里把方向取反，二者选一。
